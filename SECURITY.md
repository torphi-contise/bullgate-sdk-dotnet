# Security policy

Report security issues privately so maintainers can investigate and coordinate
a fix before exploitable details are public.

## Supported versions

Until versioned releases exist, security fixes apply to the current default
branch. Historical snapshots, local packages, and third-party forks are not
maintained by this project.

## Report a vulnerability

Email `marco@torphi.com.br` with the subject
`Security - Bullgate SDK for .NET`.

Include the affected package, type or endpoint, observed impact, minimal
reproduction, environment and version, redacted evidence, and a safe contact
method.

Do not send valid integration or delivery credentials, passwords, OTPs, reset
tokens, session tokens, flow capabilities, store proofs, or another person's
data. First describe any sensitive evidence and arrange a safer transfer.

The project aims to acknowledge reports within five business days and provide
an initial assessment within ten business days. These are communication goals,
not resolution guarantees.

Use only systems, accounts, and data you own or are authorized to test. Avoid
denial of service, social engineering, persistence, and access to third-party
data. This policy does not authorize testing Bullgate deployments, providers,
stores, or consumer applications owned by someone else.
